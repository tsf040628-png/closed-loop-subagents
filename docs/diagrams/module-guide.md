# 图表模块说明

本页按两张图中的模块说明闭环子代理的输入、角色、状态和修正规则。可先打开[交互式双图页面](https://tsf040628-png.github.io/closed-loop-subagents/)，悬停或键盘聚焦时查看关联路径，点击模块后在说明面板中查看摘要并跳转到本页。也可直接查看[架构图 SVG](role-architecture.svg)和[工作流 SVG](workflow.svg)。

## 架构图

### 用户输入

任务开始时提供目标、约束和可判断的完成标准。Planner 遇到会影响范围、验收、依赖或权限的关键不确定性时，应先询问并等待答复。

### 协调器

协调器管理状态流转、角色派发、权限边界和全局修正轮次。它根据最新共享状态安排下一项工作，并在通过最终复核后交付结果。

### 规划代理

Planner 将目标拆成可执行步骤、验收标准、证据要求和风险。相关技术任务可以先查找可借鉴方案；任务完成后，Planner 负责整合最终文件、保留重要日志并提交清理清单。

### 执行代理

Executor 一次只执行一个已批准步骤，并提交实际产物和可核验证据。Reviewer 通过后，流程才进入下一步。

### 审阅代理

Reviewer 在独立上下文中对照验收标准审查计划、每一步的产物和最终收尾。它记录通过或缺陷类型，并决定严重规划或路线错误是否需要升级 Planner 模型。

### 版本化共享状态

共享状态记录计划、步骤、产物、证据、审阅结果、重要日志和模型信息。每次状态更新保留版本，供协调器和后续角色核对；模型分配记录与运行时模型遥测分开保存。

### 交付结果

闭环复核通过后，协调器向用户返回进度、最终文件和关键记录。若任务仍有未解决项，则报告剩余问题，不标记为完成。

## 工作流图

### 规划与批准

Planner 完成拆解和验收标准后，由 Reviewer 独立审计划。只有审计划通过，且关键不确定项已获用户确认，才能开始执行。

### 逐步执行

Executor 每次完成一个获批步骤并提交证据，Reviewer 独立验收。当前步骤通过后继续下一个批准步骤；发现缺陷时进入统一修正预算。

### 集成与闭环

所有批准步骤通过后，Planner 集成最终文件并保留重要日志。Reviewer 审终稿并批准清理清单；Planner 按清单清理并提交回执，Reviewer 最后核对文件、证据、日志和状态。

### 全局修正预算

所有审阅发现共用最多 8 轮修正预算。每轮包括一次修正和一次独立复审。`PLAN_GAP`、集成和收尾问题回到 Planner；`EXECUTION_DEFECT` 回到 Executor。任何最终阶段缺陷都不能绕过预算。

### 模型升级与轮次上限

从第 4 轮起，若 Reviewer 判断存在严重规划或路线错误，可将 Planner 指派为 `gpt-6-sol / medium`；正常推进下一步不要求升级。达到 8 轮仍未完成时，流程停止并报告剩余问题，再询问用户是否授权有界追加轮次。
